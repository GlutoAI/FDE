# Project foundation: backend, frontend, and LLM layer

Create this during initialization. Follow [coding-standards](../coding-standards/SKILL.md) for all application code. The foundation is built on [Pydantic AI](https://ai.pydantic.dev/):
- **Pydantic AI owns:** the model call, native or tool-based structured output, and output validation.
- **The application owns:** contracts, configuration, vendor selection, error normalization, and provenance.

## The project template

Every project starts from the workspace's template: [`backend/`](../../../backend/) and [`frontend/`](../../../frontend/) at the workspace root. The same template is kept outside the repository as `FDEAI-A4A-fullstack-0.0.0-2.1/`. It fixes the layout:
- **Backend:** a FastAPI package named `app` in `backend/app/`. Run it from `backend/` with `uvicorn app.main:app --reload`. It has `main.py` (app plus lifespan), `database.py`, `routers/health.py` returning `{"status": "ok", "db": "connected"}`, `requirements.txt`, and SQLite at `backend/data/app.db`, which the template's `.gitignore` ignores.
- **Frontend:** Vite React TypeScript, with `src/api/client.ts` and an `/api` proxy to `127.0.0.1:8000` that strips the prefix.

Copy the template, then grow it. Keep its file names, entry points, health response shape, and CORS origins (`http://localhost:5173` and `http://localhost:3000`). Our additions go inside `backend/app/` as subpackages. Two deliberate differences from the template:
- **Health failures:** on failure, `/health` returns a safe code (`"detail": "database_unavailable"`) in a flat body rather than `str(e)`.
- **Dependencies:** `pyproject.toml` and `uv.lock` are the source of truth, and `requirements.txt` is exported from the lock, so the template's `pip install -r requirements.txt` still works.

**Lock file caveat:** the template's `frontend/package-lock.json` resolves packages from `registry.npmjs.intuit.com`, an internal registry. Where that is unreachable, `npm install` fails with "Exit handler never called!". Use the workspace root's `frontend/package-lock.json`: it has the same dependency versions, resolved from `registry.npmjs.org`.

## Why the template is built this way

- **Dependencies:** the lock resolves SQLAlchemy 2.1.1, aiosqlite 0.22.1, `mcp` 2.2.0, `fastmcp-slim` 4.0.10, and Pydantic AI 2.31.1. `mcp` 2.x renamed `FastMCP` to `MCPServer`; examples written for 1.x will not import. Keep `anthropic<1` until Pydantic AI supports the 1.x SDK: Pydantic AI 2.31.1 passes `temperature` to `messages.create()`, which anthropic 1.8.0 rejects locally before sending any request, and 0.125.0 works.
- **`models.toml`:** `default_embedding_profile` must come before the first `[table]` header, or TOML parses it into that table. `[vendor_profiles]` is what makes `smoke --live --provider anthropic` select `connection_anthropic` and `--provider openai` select `connection_openai`; every entry must name a profile of that vendor, or settings fail with `incompatible_profile`. Drop a vendor's profile and its `[vendor_profiles]` line together. `reasoning_effort = "none"` keeps the one-line probe from spending reasoning tokens on GPT-5.x.
- **Model IDs:** `gpt-5.4-mini-2026-03-17` and `claude-opus-5-5` (with anthropic 0.125.0) passed the live probe with native structured output on 2026-09-27. Pydantic AI 2.31.1 does not list `claude-opus-5-5` by name; it gets native output because the structured-output check matches the `claude-opus-5` prefix. Recheck availability when a project starts. Opus is the most expensive Claude tier; choose models per role during evaluation.
- **Docker installs from `requirements.txt`:** the image installs with pip from the exported, pinned file, so it needs no `uv` and gets the lock's versions. Re-export after every `uv lock`, or the image drifts from the lock.
- **Mirrored layout in the image:** `DEFAULT_PROJECT_ROOT` is `parents[3]` of `app/core/settings.py`, so `/project/backend/app/...` makes `/project` the root. A missing `/project/.env` is fine; settings fall back to TOML defaults and the explicit environment.
- **Vite 8 and `@vitejs/plugin-react` 6:** the template's Vite 5.4 pulled in esbuild 0.21, and `npm audit` flagged both (GHSA-67mh-4wv8-2f99: any website could send requests to the dev server and read the responses). Vite 8.3.1 bundles with Rolldown and has no esbuild dependency; `npm audit` reported 0 vulnerabilities on 2026-09-27. It needs Node `^20.19` or `>=22.12`, which `node:22-alpine` meets. `scripts/check.sh` runs `npm audit --audit-level=moderate`, so a new advisory fails the gate until the dependency is upgraded.
- **nginx, not the Vite dev server:** the UI container serves the production build and forwards `/api/` the same way the Vite proxy does, so the browser uses one origin and `vite.config.ts` is unchanged.
- **Container security:** no keys and no `--env-file`, because nothing is interpolated yet. Both processes run as non-root users, ports bind to loopback, and runtime state lives in a named volume. `ENV OPENSSL_armcap=0` in the API image stops `cryptography` from crashing (SIGILL) on Apple M4 Docker VMs; the MCP client passes it to child servers through `PLATFORM_VARIABLES`.
- **Deliberate shortcuts:** base images are pinned by tag, not digest. There is no data mount, so `data-import` runs on the host. `--live` commands run on the host until a service gets an explicit key mapping.

## Contracts

1. **`llm/contracts.py`.** `Contract(BaseModel)` is frozen, forbids extra fields, and is strict. On it:
   - **`ModelProfile`:**
     - `provider` is `Literal["fixture", "openai", "anthropic"]`.
     - It also holds `model_id`, `timeout_seconds`, `max_output_tokens`, and an optional `reasoning_effort`.
     - Keep the diagnostic caps (60 s, 256 tokens) only on the connection profile's values, not as the field bounds. Business agents will need larger limits.
   - **`AgentResult[OutputT]`:** the validated output plus provenance: `provider`, `model_id`, `prompt_version`, `prompt_sha256`, and token usage (`None` when unknown, never a fabricated zero).
   - **Prompt models:** `PromptReference` (a path-safe agent name and version), `PromptTemplate` (agent, version, system, user, optional `model_profile` and `model`), and `LoadedPrompt` (a template plus the SHA-256 of its bytes).
2. **Agent contracts: `agents/<agent>/models.py`.** Each agent has an `<Agent>Input` and an `<Agent>Output`. The output class is the schema Pydantic AI enforces. These are the example input/output contracts every later agent copies:

```python
class ConnectionInput(Contract):
    """A synthetic probe request; it carries no business data."""

    expected_marker: Literal["CONNECTION_OK"] = Field(
        default="CONNECTION_OK", description="Fixed diagnostic marker the model must return"
    )


class ConnectionOutput(Contract):
    """The structured result the model must return for the probe."""

    status: Literal["ok"] = Field(description="Successful diagnostic response")
    marker: Literal["CONNECTION_OK"] = Field(description="Exact requested diagnostic marker")
```

A business agent follows the same shape. For example, a later `ForecastInput` holds tenant and date fields, and a `ForecastOutput` holds integer-cent amounts and cited record IDs. Neither exists at initialization.

## One base agent, one provider per vendor

Vendor differences live in `ModelProvider` implementations, never in agent classes. An agent is chosen by its role; its vendor is chosen by `config/models.toml` and YAML. Switching an agent from GPT to Claude is a configuration change.

```python
class ModelProvider(ABC):
    """A configured model vendor: its model, its settings, its output mode, and its SDK errors."""

    @abstractmethod
    def get_model(self) -> Model:
        """Return the configured Pydantic AI model without making requests."""

    @abstractmethod
    def build_model_settings(self, profile: ModelProfile) -> ModelSettings:
        """Return shared limits plus this vendor's own keys.

        Raises:
            ConfigurationError: The profile asks for a setting this vendor or model cannot honor.
        """

    @abstractmethod
    def build_output_spec(self, output_type: type[OutputT]) -> NativeOutput[OutputT] | ToolOutput[OutputT]:
        """Return native JSON-schema output when the model supports it, tool output otherwise."""

    @abstractmethod
    def classify_sdk_error(self, error: BaseException) -> str | None:
        """Return a safe error code for this vendor's SDK transport errors, or None if unknown."""
```

| Method | Fixture | OpenAI | Anthropic |
|---|---|---|---|
| `get_model` | `TestModel` scripted with a valid output | `OpenAIResponsesModel` on an injected `AsyncOpenAI` | `AnthropicModel` with `AnthropicProvider(anthropic_client=...)` on an injected `AsyncAnthropic` |
| `build_model_settings` | Shared keys only | `OpenAIResponsesModelSettings` with `max_tokens`, `timeout`, `openai_store=False`, and `openai_reasoning_effort` if set | `AnthropicModelSettings` with `max_tokens`, `timeout`, and a translation of `reasoning_effort` to the Anthropic effort/thinking keys, or `ConfigurationError` |
| `build_output_spec` | `NativeOutput` | `NativeOutput` | `NativeOutput` if `model.profile["supports_json_schema_output"]`, else `ToolOutput` |
| `classify_sdk_error` | `None` | `openai.APITimeoutError` → `timeout`, `APIConnectionError` → `network` | `anthropic.APITimeoutError` → `timeout`, `APIConnectionError` → `network` |

Current Pydantic AI (2.31.1) marks native structured output for Claude Haiku 4.5, Sonnet 4.5 and later, Opus 4.1 and later, and the 5 family. Older Claude models use `ToolOutput`. In that version `tool_calls_limit` counts only function tools, not the output tool, so `tool_calls_limit=0` still holds.

**`llm/runtime.py`** is vendor-neutral and imports no vendor SDK:
- `build_agent_runtime(provider, prompt, profile, *, input_type, output_type)` builds a Pydantic AI `Agent`. It takes the output from `provider.build_output_spec(output_type)`, the instructions from the prompt's system text, and the settings from `provider.build_model_settings(profile)`, with `retries=0`.
- `normalize_model_errors(provider)` maps failures to safe codes:
  - Pydantic AI's `ModelHTTPError` → a code by status: 401 `authentication`, 403 `permission`, 404 `model_unavailable`, 429 `rate_limit`, 400 `invalid_request`, anything else `provider_error`.
  - `ModelAPIError` and bare SDK errors → `provider.classify_sdk_error`, falling back to `network`.
  - `UnexpectedModelBehavior`, `UsageLimitExceeded`, and `ValidationError` → `AgentOutputError`.
  - `UserError` → `ConfigurationError`.
- A provider may refine a status using a known code from the error body (OpenAI's `insufficient_quota` → `quota`). Messages are never surfaced.

**`agents/base.py`.** `BaseAgent[InputT, OutputT](ABC)` receives the runtime, prompt, profile, and `input_type` through `__init__`, and performs no I/O. `run_agent` is the concrete template method:
1. Revalidate the request against `input_type` (`AgentInputError`).
2. Run one request under `asyncio.timeout` and `UsageLimits(request_limit=1, tool_calls_limit=0)`, inside `normalize_model_errors`.
3. Call the abstract `_validate_output(request, output)` hook.
4. Build an `AgentResult`, rejecting a live response that did not finish normally or lacks a model name.

The base is not a tool-loop framework: Pydantic AI owns tool loops, and LangGraph (if adopted) owns workflow state.

**`bootstrap.py`.**
- **Choosing the vendor:** `open_model_provider(profile, settings)` is an async context manager. It dispatches on `profile.provider` to one factory per vendor.
- **What each factory does:** it opens its SDK client with the vendor's key from `Settings`, a pinned `base_url`, `max_retries=0`, and the profile timeout. It yields the provider and closes the client on exit. A missing key for the selected vendor raises `ConfigurationError` naming the variable, never its value.
- **The fixture factory** opens nothing.
- **Agent assembly:** `create_connection_agent(location, settings)` resolves the prompt and profile, opens the provider, and yields the agent. `build_connection_agent(provider, prompt, profile)` is the pure assembly step used by tests.
- **Where SDKs appear:** only bootstrap and `llm/providers/` import vendor SDKs.

Adding a vendor means one provider class, one factory, one `Literal` value, and one key field. The agents do not change.

## Configuration

- **Where things live:** `ProjectLocation(root=<project>)` derives every path from the explicit project root, and no parent directory is searched:
  - `env_file` is `<project>/.env`;
  - `data_root` is `<project>/data`;
  - `backend_root`, `config_dir` and `state_dir` are `backend/`, `backend/config/` and `backend/data/`.
  - `DEFAULT_PROJECT_ROOT` (three levels above `app/core/settings.py`) is the default for the CLI and `app.main:app`, so both work when run from `backend/`.
- **Settings precedence:** `default.toml` < `<env>.toml` < `.env` < process environment.
- **Keys:** one per vendor, `<PREFIX>_OPENAI_API_KEY` and `<PREFIX>_ANTHROPIC_API_KEY`. Both are `SecretStr` and excluded from `repr`; blank values count as absent. Hosted embeddings reuse the OpenAI key.
- **Database:** `<PREFIX>_DATABASE_URL` is also a `SecretStr`, since a PostgreSQL URL can carry a password. When it is blank, the backend uses SQLite at `backend/data/app.db`, the template's location.
- **Fails with `ConfigurationError`:** unknown TOML keys, unsupported environments, and any enabled external-action flag.
- **Model selection**, in rising priority:
  1. `models.toml` `default_profile`.
  2. `roles[<agent>]`.
  3. The prompt YAML's `model_profile`.
  4. The prompt YAML's `model`.
  5. `<PREFIX>_LLM_PROVIDER` / `<PREFIX>_LLM_MODEL`.
- **Fixture isolation:** YAML and environment overrides apply only in live mode. Fixture mode always resolves the `fixture` profile, so a YAML `model` can never make a fixture run live.
- **Catalog checks:** every role and profile reference must exist. A fixture provider selected for live mode is an error, and so is a `model` override whose vendor differs from its profile's.
- **Model IDs:** agents never hard-code them in Python.
- **Live calls:**
  - `smoke` is offline regardless of settings.
  - `smoke --live --provider <vendor>` authorizes exactly one hosted request to that vendor's connection profile. Without `--provider`, it uses the connection role's configured vendor. The flag never rewrites `.env`.
  - The API's diagnostics route is fixture-only. No HTTP route can trigger a paid request at initialization.
- **Developer values:** preserve them. When the user supplies a key for this project, write only its field in `.env` (mode `0600`). Never put it in templates, source, YAML, command arguments, reports, frontend code, or git.
- **Prompts:** they live at `backend/app/prompts/<agent>/v<N>.yaml`, loaded through `importlib.resources`.
  - Load them with `yaml.safe_load` and validate against `PromptTemplate`; the file's agent and version must match the reference.
  - Hash the original bytes.
  - Increment versions deliberately.

```yaml
agent: connection
version: 1
# null inherits config/models.toml; name a profile for vendor/limit overrides.
model_profile: null
# null inherits the selected profile's model; the <PREFIX>_LLM_MODEL override wins.
model: null
system: |
  You are a connection diagnostic. Return a JSON object matching the supplied
  output schema, with status "ok" and marker equal to the input expected_marker.
  Include no explanation or additional fields.
user: Validate the model connection using this typed synthetic input.
```

## API and frontend

- **`app/main.py`:** keeps the template's shape, a lifespan plus a module-level `app`, but builds it through `create_app(location)` so tests can point it at a temporary project.
  - The lifespan loads settings, opens the database with `open_database`, and stores `location`, `settings`, and `engine` on `app.state`. It opens no model client.
  - CORS allows the template's origins, `http://localhost:5173` and `http://localhost:3000`.
  - Routers declare `response_model` and use no `/api` prefix, because Vite strips it.
- **`app/database.py`:** the template's database module, over our async engine. It holds `get_engine(request)`, a FastAPI dependency, and `is_database_reachable(engine)`, which runs `SELECT 1` and returns a bool.
- **`GET /health` (`routers/health.py`):**
  - It returns the template's body, `{"status": "ok", "db": "connected"}`, using `response_model_exclude_none=True`.
  - On failure it returns 503 with `{"status": "error", "db": "disconnected", "detail": "database_unavailable"}`: a flat body with a safe code, unlike the template's `str(e)`.
  - It makes no model call and exposes no key presence.
- **`POST /diagnostics/connection` (`routers/diagnostics.py`):** forces fixture mode, runs `ConnectionAgent`, and returns `AgentResult[ConnectionOutput]`. `<Package>Error` becomes a 502 with the safe code.
- **`frontend/src/api/client.ts`:**
  - `HealthResponse` (`status`, `db`, `detail?`) and `checkHealth()`, which resolves with `status: "error"` and the backend's safe `detail` (or `HTTP <status>`) on a non-2xx response.
  - `ConnectionOutput`, `AgentResult<T>`, and `runConnectionCheck()`, which throws with the backend's safe `detail`.
  - Error bodies are read as `unknown` and narrowed; no `any` reaches a component.
  - Keep the interfaces in sync by hand, since there is no code generation.
- **`hooks/` and `components/`:** `useHealthStatus` fetches on mount and on retry; `useConnectionCheck` runs on demand. `HealthCard` and `ConnectionCard` render their props and report clicks through `onRetry` and `onRunCheck`. `App.tsx` composes them and fetches nothing itself.
